# What this tutorial is about

This is a beginner guide to Bash. Bash is the shell used on Linux and macOS systems. It lets you use your pc through text commands instead of clicking through menus.

In plain terms: Bash is how you talk to your pc in the terminal.

---

# Common terms

Before we start, here are a few words you will see a lot:

- Terminal: the text window where you type commands
- Shell: the program that reads and runs those commands
- Bash: a popular shell on Linux and macOS
- Command: a text instruction like `ls` or `pwd`
- Directory: another word for a folder
- File: something stored on your pc, like a document or script

---

# How this tutorial works

This tutorial is built one concept at a time.

You are not going to get hit with a giant wall of commands and expected to memorize everything. You will learn in small chunks, practice the basics, and build from there.

Each section usually includes:

- what the command or idea is
- why it actually matters
- how to use it in practice
- a clear example
- a quick explanation of what happened
- a few lessons that connect the idea to real usage

The goal is not to memorize syntax like a robot. The goal is to understand the logic behind the commands and actually know what is happening.

You learn a few things, use them, then combine them later. That is where the real understanding shows up. Once the basics click, you can start making projects instead of just running random commands and hoping for the best.

This is not just copy-paste Bash. You are learning how programs are structured, how input works, how decisions are made, and how small pieces fit together into a bigger system.

You will start noticing patterns: variables hold data, commands produce output, conditionals decide what happens next, loops repeat work, and functions group steps into reusable pieces. That is the actual skill. Once that clicks, the commands stop feeling random and start feeling like tools.

---

# Before you start practicing

- use a terminal or VS Code terminal
- do not panic if something fails. Spend a minute messing with it, read the error, and try to fix it yourself before you give up. If you are stuck, do not be scared to Google it or check the docs. At least now you understand what the command is doing, how it works, and why it failed. The next time you hit the same issue, you will probably think, “oh, this is the part I need to fix.”
- try the examples yourself
- if a command breaks, that is part of learning
- if you missed a space or typo, fix it and try again

The best way to learn Bash is by using it. Not by reading forever.
